# /ckw:execute-phase — Draft Content Per Task Plan

## Purpose
Execute the planned tasks for a phase, drafting content with fresh context per task. This is where the actual knowledge work gets done — writing, analysis, synthesis. Each task gets a clean context loaded with only what it needs.

## Usage
```
/ckw:execute-phase <N> [--task T] [--wave W] [--revisions] [--headless]
```

- `N`: Phase number (required)
- `--task T`: Execute only task T (useful for re-doing a specific task)
- `--wave W`: Execute only wave W (useful for stepping through waves manually)
- `--revisions`: Execute only revision tasks (R*-PLAN.md) generated by /ckw:review-phase

## What This Command Does

Read the phase plan, then spawn **ckw-executor** agents with fresh contexts — one per task.

### Step 1: Load Phase Plan

Read `.planning/phases/{NN}-{phase-name}/PHASE-PLAN.md` to get:
- Task list with dependencies
- Wave execution order
- Context loading instructions per task

Verify the phase is planned (check STATE.md). If not, suggest: "This phase hasn't been planned yet. Run /ckw:plan-phase [N] first."

### Step 2: Determine Execution Scope

- **Default:** Execute all remaining tasks in dependency order (wave by wave)
- **--task T:** Execute only task T (skip dependency check — user knows what they're doing)
- **--wave W:** Execute all tasks in wave W
- **--revisions:** Execute only revision task plans (R*-PLAN.md files) generated by `/ckw:review-phase`. These use the same task plan format — the executor processes them identically to regular tasks. Revision tasks reference the original draft and fix specific P1 issues.

Check which tasks are already completed (from STATE.md / task SUMMARY files).
Skip completed tasks unless `--task` explicitly targets one.

### Step 3: Execute Tasks (Wave by Wave)

For each wave, execute tasks in the wave. Independent tasks within a wave CAN be parallelized by spawning multiple ckw-executor agents.

**For each task:**

1. **Spawn ckw-executor with fresh context** containing ONLY:
   - Files listed in the task plan's "Context to Load" section
   - Nothing else — no conversation history, no other task outputs
   - This prevents context degradation across tasks
   - If a reference file listed in the task plan doesn't exist, warn the user and continue with available context: "Reference [path] not found — proceeding without it. Run /ckw:import-reference to add missing references."

2. **The executor agent:**
   a. Reads the task plan instructions
   b. Reads the specified reference materials
   c. Drafts the content according to instructions
   d. Saves output to the specified file in `drafts/`
   e. Runs quality criteria self-check
   f. Flags any [ACTION REQUIRED] items
   g. Generates `{N}-SUMMARY.md` with:
      - What was produced
      - Decisions made during drafting
      - Items flagged for human review
      - Self-assessment against quality criteria

3. **After each task completes — save progress:**

   **If local/git repo:**
   ```bash
   git add drafts/[output-file]
   git add .planning/phases/{NN}-{phase-name}/{N}-SUMMARY.md
   git commit -m "CKW: Phase [N] Task [T] complete — [task name]"
   ```

   **If Google Drive / cloud storage:** Skip git. Files are auto-saved by Drive. STATE.md timestamps provide the audit trail.

4. **Update STATE.md:**
   ```yaml
   phase_[N]_task_[T]_status: completed
   phase_[N]_task_[T]_commit: [git hash]
   last_updated: [ISO date]
   ```

### Step 4: Cross-Task Coherence Check

After all tasks in a wave complete (if wave has >1 task), perform a real coherence check — this is NOT a quick scan:

1. **Re-read each task's output alongside the others from this wave**
2. **Check for contradictions** — do any drafts make claims that conflict with each other?
3. **Check terminology consistency** — are the same concepts named the same way across drafts?
4. **Check tone consistency** — do all drafts match the voice specified in CONTEXT.md?
5. **Check for duplicated content** — did multiple tasks cover the same ground?

If you find inconsistencies, fix them NOW before moving to the next wave — don't defer to the review phase. Small fixes now prevent compounding errors later.

### Step 5: Progress Report

After execution completes (or is interrupted):

```
Phase [N] execution progress:

✅ Task 1: Executive summary drafted (drafts/exec-summary.md)
✅ Task 3: Team overview drafted (drafts/team-overview.md)
⏳ Task 2: Competitive positioning (depends on Task 1 — ready to execute)

Completed: 2 of 3 tasks
[ACTION REQUIRED] items: 2
  • Task 1: Client revenue figure needs verification
  • Task 3: Confirm Rachael Azulay is still primary PM

Next:
  /ckw:execute-phase [N]     Continue with remaining tasks
  /ckw:review-phase [N]      Review completed drafts
  /ckw:progress              Full project status

Drafts are in markdown. To share with stakeholders:
  Use the export-document skill to convert to .docx, .pptx, or .pdf
```

## Executor Agent Rules

The executor agent's full content quality rules, context discipline, output format, and self-review gate are defined in `agents/ckw-executor.md`. That agent definition is the single source of truth — do not duplicate rules here.

## Pipeline Mode

**`--headless` behavior:** Execute all tasks without pausing between waves or prompting the user.

- **Wave-by-wave execution:** Execute all waves sequentially without confirmation between waves. Do not pause for user input.
- **Cross-task coherence check (Step 4):** Still runs. If inconsistencies are found, fix them automatically (same as interactive behavior).
- **Missing references:** Log a warning and continue. Do not prompt for import.
- **ACTION REQUIRED items:** Flag them in SUMMARY files as normal, but do not prompt the user mid-execution.
- **All file writes and git commits:** Proceed without confirmation.
- **Progress report (Step 5):** Still generated with full details.

## Error Handling

- If phase plan doesn't exist, suggest /ckw:plan-phase
- If a task fails (executor errors out), save partial work and note in STATE.md
- If context budget is exceeded, warn and suggest splitting the task
- If a dependency isn't met (prior task not complete), skip and report
- If reference material in the task plan is missing, warn and proceed with available context
